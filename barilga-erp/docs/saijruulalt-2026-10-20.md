# Сайжруулалтын тэмдэглэл — 2026-10-20

Өмнөх: [saijruulalt-2026-10-19.md](saijruulalt-2026-10-19.md). Эрхийн тайлбар: [erh-ba-uureg.md](erh-ba-uureg.md).

## 1. Хэмжих нэгж

- Нэгж одоо **хадгалагдсан жагсаалтаас** сонгогдоно (ш, ширхэг, шуудай, хуудас, кг, тн, м, м², м³, л, боодол, ороомог, хайрцаг, багц).
- Бараа бүртгэх, бараа орлого дээр **«+ Шинэ нэгж»** сонгоод нэр бичихэд жагсаалтад нэмэгдэнэ (бараа засах эрхтэй хүн).
- **Компанийн мэдээлэл → Хэмжих нэгж** хэсэгт нэмэх, хасах, дарааллыг өөрчилнө. Нэгж хассан ч хуучин бараанд нөлөөлөхгүй.

## 2. Дагалдах бараа

- Бараа засах цонхны «Дагалдах бараа» мөр бүрт **хайлтын хайрцаг**: бүртгэлтэй бараанаас нэр, код, баркодоор хайж сонгоно; нэр, нэгж нь өөрөө бөглөгдөнө. Гараар бичих нь хэвээр.
- «0,5» гэж таслалтай бичсэн тоо өмнө нь **чимээгүй устдаг** байсныг зассан.
- **Таслалын дүрэм** (бараа бүртгэл, бараа орлого, үлдэгдэл засах, дагалдах барааны тоо): «0,5» = 0.5, «0,125» = 0.125. Харин «1,250» эсвэл «1,250,000» гэх мэт мянгатын таслал шиг тоог **хүлээж авахгүй** — «1250» эсвэл «1.25» гэж бичнэ үү гэж анхааруулна (өмнө нь 1.25 болж буруу хадгалагдах эрсдэлтэй байсан). Бараа орлогод ийм тоо улаан хүрээтэй байхад тэр барааг дахин уншуулбал тоо нь «1» болж солигдохгүй, хэвээр үлдэнэ.
- Дагалдах бараа одоо ч **зөвхөн харагдана** — үлдэгдлээс хасагдахгүй, үнэд нөлөөлөхгүй (энэ дүрмийг өөрчлөх эсэх нь таны шийдвэр).

## 3. Ирц — уян хатан болгосон

| Шинэ боломж | Хэрхэн |
|---|---|
| **Миний ирц** (цэсэнд бүх ажилтанд) | Ажилтан өөрөө **«Ирлээ / Явлаа»** дарна. Сарын календарь, өнгөөр тэмдэглэгээтэй. |
| **Менежер батлах** | Ажилтны өөрөө бүртгүүлсэн ирц менежер «Батлах» дартал ирсэн өдөрт тооцогдохгүй. (Тохиргоо: унтраах / батлуулах / шууд тооцох — админ сонгоно.) |
| **Чөлөө хүсэх** | Цалинтай/цалингүй чөлөө, өвчтэй, ээлжийн амралт, томилолт — өдрүүд, шалтгаан. Менежер зөвшөөрөх эсвэл шалтгаантай татгалзана. |
| **Өдрийн төлөв** | Менежер тухайн өдөрт «Тасалсан», «Өвчтэй», «Чөлөө»… гэж шууд тэмдэглэнэ. |
| **Ирц нэмэх, устгах** | Мартсан өдрийг шалтгаантай нэмэх, буруу бүртгэлийг шалтгаантай устгах. |
| **Сарын хүснэгт** | Хүн × өдөр, үсэг/өнгөөр: ирсэн, хоцорсон, батлаагүй, төлөв, баярын өдөр, «?» = юу ч бүртгэгдээгүй өдөр, «–» = ажилд орохоос өмнө. Нүдэн дээр дарж засна. |
| **Нийтийн амралтын өдөр** | Админ огноо нэмнэ — ажлын өдөрт тооцохгүй. |
| **Мэдэгдэл** | Менежерт: шийдэх чөлөөний хүсэлт, батлах ирц. Ажилтанд: хүсэлтийн хариу. |

- **Зөвшөөрсөн чөлөөг** ажилтан эхлэхээс нь өмнө өөрөө буцааж болно. Эхэлсний дараа менежер **Ирц → Хүсэлтүүд → «Бүгд»** дээрх зөвшөөрсөн хүсэлтийн **«Цуцлах / богиносгох»** товчоор бүхэлд нь цуцлах, эсвэл «Эрт ирсэн» гэж сүүлийн өдрийг сонгоно — түүнээс хойшхи өдрүүдийн төлөв арилна. Цалин олгосон сарыг өөрчлөхгүй.
- **Шөнө дундаас хойш явсан** (жишээ нь 23:30-д ирээд 00:40-д явсан) ажилтан «Явлаа» дарж болно — 16 цаг хүртэлх ээлжийг хэвийн хаана. Түүнээс удаан нээлттэй үлдсэн ирцийг менежер «засах»-аар оруулна.
- Менежер **өөрийн ирцээ** «Ирц» самбараас «Ирсэн» дарж бүртгэхгүй — бусадтай адил «Миний ирц»-ээс бүртгүүлж, өөр менежер (эсвэл админ) батална.
- Цалин олгосон сарын батлаагүй ирц «Батлах» жагсаалтад гарахгүй.
- Огноо бодит өдөр байх ёстой (2026-02-30 гэх мэтийг хүлээж авахгүй).

Бүх засвар «Засварын түүх»-д хэн, яагаад гэдэгтэйгээ үлдэнэ. Өөрийн ирцийг (админаас бусад) өөрөө батлах, засахгүй.

**Цалинд:** төлөвүүд цалинг **автоматаар өөрчлөхгүй**. Цалингийн хуудсанд «Тасалсан 2 · Цалингүй чөлөө 1» гэж харагдана — суутгалыг менежер гараар бичнэ. Аль төлөвт хэдэн хувь төлөхийг эзэн, нягтлантай тохирох хэрэгтэй (ээлжийн амралт, өвчний тэтгэмж хуулиар зохицуулагддаг).

## 4. Нэхэмжлэх — POS-оос шууд, задгай

- POS дээр **«Нэхэмжлэх (дараа шилжүүлгээр)»** сонголт. Худалдан авагч **заавал биш** — сонгоогүй бол нэхэмжлэх дээр «Төлөгч» хоосон мөртэй («……») хэвлэгдэнэ. Товч нь «Нэхэмжлэх гаргах».
- Бараа **нөөцлөхгүй**, мөнгө орсны дараа («✓ Мөнгө орсон») олгогдоно. Касс нээх шаардлагагүй.
- **Нэхэмжлэх илгээх хаана вэ?** Захиалгын хуудас дээрх нэхэмжлэхийн хэсэгт: **📤 Хуваалцах** (утсан дээр Viber, Messenger…), **SMS**, **Холбоос хуулах**, **Имэйл**, **Хэвлэх / PDF**. Илгээсэн бүр тэмдэглэгдэнэ.
- **Авагчийг дараа нь** нэмэх, солих: тэр хэсэгт хайх эсвэл «+ Шинэ» (байгууллага/хувь хүн) бүртгэнэ. Байгууллага бол И-баримт байгууллагын РД-тэй гарна.
- «……» нэхэмжлэхэд анх авагч нэмэхэд холбоос **хэвээр**. Касс дээр гараар бичсэн авагчийг ижил утасны дугаартай бүртгэлтэй харилцагчаар солиход ч хэвээр. Харин **өөр авагчаар солиход** (бүртгэлтэй эсвэл гараар бичсэн аль ч авагчийг) нэхэмжлэхийн болон захиалгын хяналтын **холбоос шинэчлэгдэнэ** — өмнөх авагчид илгээсэн холбоос ажиллахаа больж, шинэ авагчийн мэдээллийг харуулахгүй. Шинэ холбоосыг дахин илгээнэ (илгээсэн тэмдэглэгээ 0 болно).
- **Хувааж төлөхөд** нэхэмжлэхийн хэсгийг зөвхөн **бэлэн эсвэл карттай** хамт хувааж болно. QPay, шилжүүлэг, «Дараа төлөх», гэрээтэй хамт хуваахгүй: нэхэмжлэх төлөгдөөгүй бүх дүнг шаарддаг, мөн нэг «Мөнгө орсон» хүлээгдэж буй бүх шилжүүлгийг зэрэг баталдаг тул нэхэмжлэх буруу дүн харуулах, бараа эрт олгогдох эрсдэлтэй байсан.
- Нэхэмжлэх нь хүчинтэй захиалга «Төлбөр хүлээсэн хэвээр захиалга» мэдэгдэлд гарахгүй (хугацаа хэтэрсэн нэхэмжлэх мэдэгдэлд гарна). Нэхэмжлэхийг нь цуцалсан ч төлөгдөөгүй захиалга, эсвэл нэхэмжлэхийн модуль унтарсан үед тэр мэдэгдэлд дахин гарна.
- Захиалгын хуудас дээрээс нэхэмжлэх үүсгэх, цуцлахад «Гүйлгээний утга» шууд шинэчлэгдэнэ (хуудсаа дахин ачаалах шаардлагагүй).
- **Нэхэмжлэхүүд** хуудаст «+ Шинэ нэхэмжлэх», «Төлөгчгүй» шүүлтүүр, мөр бүрт холбоос хуулах / хэвлэх / төлөгч нэмэх.
- Төлөгдөөгүй нэхэмжлэхийг цуцлахад захиалга нь бас цуцлагдана (өлгөөтэй үлдэхгүй).
- Хэвлэхэд нэхэмжлэхийн дугаар (NH-…), төлөх хугацаа заавал гарна; «Гүйлгээний утга» бүх газар NH дугаар.

## 5. Үнийн жагсаалт — сонгосон бараагаар

- **Агуулахын үлдэгдэл**: бараануудыг тэмдэглээд доод мөрөөс «Үнийн жагсаалт хэвлэх» — зөвхөн сонгосон бараа (эсвэл шүүсэн ангилал).
- **Үнийн жагсаалт** хуудаст: сонгох багана, «Сонгосныг хэвлэх (N)», «Харагдаж буйг хэвлэх».
- **Холбоос илгээх**: бүх жагсаалт / сонгосон бараа / ангилал, нэр, дуусах огноотой холбоос үүсгэнэ. Үүсгэсэн холбоосуудыг жагсааж хуулах, хуваалцах, **хаах** боломжтой. Жижиглэнгийн үнээр ч холбоос илгээнэ.
- Хаасан эсвэл хугацаа дууссан холбоос харилцагчид «хугацаа дууссан» гэж харагдана. Өмнө илгээсэн холбоосууд хэвээр ажиллана.
- Дуусах огноотой холбоос нь өдөр тутмын «Холбоос хуулах» холбоос болж **ашиглагдахгүй** — өдөр тутмын холбоос тэр огноонд зогсохгүй.
- Нэрэндээ таслалтай ангилал («Будаг, шавар» гэх мэт) зөв шүүгдэнэ.
- Холбоос бүрийг тусад нь хаана — нэгийг хаахад өөр хүнд илгээсэн (нэртэй, огноотой, сонгосон бараатай) холбоосууд хэвээр ажиллана.
- Харилцагч хаагдсан/хугацаа дууссан холбоос нээвэл энгийн тайлбар харна; ажилтанд зориулсан техникийн мессеж харилцагчид харагдахгүй.
- Хайлтаар юу ч олдоогүй үед «Харагдаж буйг хэвлэх» **идэвхгүй** — өмнө нь бүх каталогийг хэвлэх эрсдэлтэй байсан. Баркод/үнийн хуудсанд нэг удаад 200 хүртэл бараа сонгоно.
- Агуулахын ажилтан ч жижиглэнгийн үнийн жагсаалт хэвлэж чадна (өмнө нь алдаа гардаг байсан).

## 6. Утсан дээр хэрэглэх

- Бүх цонх (харилцагч, хэрэглэгч, буцаалт, касс…) утсан дээр **гүйлгэгддэг** болсон — өмнө нь урт маягтын «Хадгалах» товч дэлгэцээс гарч алга болдог байсан.
- Утсан дээр оролт томордоггүй (16px), товчнууд хуруугаар дарахад хангалттай том.
- **Карт хэлбэртэй жагсаалт**: захиалга, бараа, бараа орлого, нэхэмжлэх, хэрэглэгч, шилжүүлэг, ирц.
- Цэс: гадна дарахад хаагдана, холбоос дарахад хаагдана. Цэс нээлттэй үед мэдэгдлийн хонх дарахад жагсаалт нь цэсний дээр харагдана.
- **Цонхонд юм бичсэн бол** Esc эсвэл цонхны гадна санамсаргүй дарахад «Бөглөсөн мэдээлэл хадгалагдахгүй. Хаах уу?» гэж асууна (касс хаах тоолсон дүн, эрхийн тохиргоо, харилцагч, шилжүүлгийн дутуу ирсэн тоо гэх мэт). ✕ эсвэл «Болих» дарвал шууд хаагдана.
- Тайлангийн табууд, шүүлтүүрүүд хажуу тийш гүйлгэгддэг нэг мөр.

## 7. Шалгалтаар олж зассан алдаанууд

Хийсэн ажлыг тусдаа шалгагчид эсрэг талаас нь шалгаж, 23 алдаа илрүүлж бүгдийг зассан. Гол нь:

- Нэхэмжлэхийн авагчийг солиход хуучин холбоос шинэ авагчийн мэдээллийг харуулдаг байсан (дээрх).
- Нэхэмжлэх + QPay хуваалт давхар төлбөр шаардаж болох байсан (дээрх).
- Ирц засах эрх өгөгдсөн (менежер биш) ажилтан менежерүүдийнхээ ирцийг засах, өмнөх өдрийн нээлттэй ирцийг өнөөдрөөр хаах (олон цаг болж хуурамчаар нэмэгдэх), цалин олгосон сарын ирцийг батлах боломжтой байсан — хаасан.
- Мэдэгдлээс «Хүсэлтүүд» рүү ороход хуудас нээлттэй байвал таб солигддоггүй байсан.
- Цонхны гадна дарж хаахад маягт санамсаргүй хаагдах, бөглөсөн шилжүүлэг/буцаалт асуулгүй хаагдах — асуудаг болсон.
- Ажилд орохоосоо өмнөх өдрүүд «тасалсан» мэт харагддаг байсан.

Засварыг дахин шалгахад дараах дутуу зүйлс олдож, мөн зассан (2-р шат):

- Шөнө дундаас хойш «Явлаа» дарахыг хаачихсан байсан → 16 цаг хүртэлх ээлжийг хэвийн хаадаг болгосон.
- Менежер зөвшөөрсөн чөлөөг цуцлах/богиносгох товч байгаагүй → нэмсэн; «2026-10-32» гэх мэт огноо, хоёр менежер зэрэг богиносгох тохиолдлыг хаасан.
- Менежер өөрийн ирцийг самбараас шууд батлагдсан байдлаар бүртгэж чаддаг байсан → хаасан.
- Гараар бичсэн авагчийг солиход холбоос хуучнаараа үлддэг байсан; нэхэмжлэх + шилжүүлэг хуваалт бүх дүнг шаарддаг байсан → зассан.
- «0,125» гэх мэт зөв бутархайг буруу гэж үздэг байсан → зассан.
- Хүсэлтээс ирсэн 200-аас урт тайлбартай өдрийн төлөвийг солих боломжгүй байсан → 300 тэмдэгт болгосон.
- Нэхэмжлэхийг нь цуцалсан төлөгдөөгүй захиалга ямар ч мэдэгдэлд гардаггүй байсан → зассан.

## Шийдвэр хүлээж буй зүйлс

- Ирцийн төлөв бүр цалинд хэрхэн нөлөөлөх (цалинтай чөлөө 100%? тасалсан бол торгууль? ээлжийн амралтын цалин) — нягтлантай.
- Дагалдах барааг үлдэгдлээс хасах эсэх.
- Төлөгдөөгүй нэхэмжлэхийг N хоногийн дараа автоматаар цуцлах эсэх.
